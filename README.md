# Плай

Сайт для любителів хайкінгу та гірських походів у Карпатах. 
Він допомагає знайти маршрут, оцінити його складність і запланувати похід.

Користувач може переглядати каталог маршрутів і шукати їх за назвою вершини чи маршруту. 
Результати можна фільтрувати за складністю та тривалістю (одноденний чи з ночівлею) і 
сортувати за кілометражем, набором висоти чи популярністю. На сторінці маршруту є детальний опис, кілометраж, 
перепад висот і список необхідних речей, які варто взяти з собою.

Маршрути згруповані за гірськими масивами (Чорногора, Ґорґани, Мармароси, Свидовець тощо) 
і за стартовими селами/населеними пунктами (Дземброня, Кваси, Ворохта, Ясіня тощо). 
Можна відкрити масив або село і побачити всі пов'язані з ними маршрути.

Зареєстрований користувач додає маршрути до свого «рюкзака», а потім планує похід. 
Усі заплановані та пройдені походи зберігаються в профілі, який можна редагувати.

Адміністратор може додавати, змінювати й видаляти маршрути, масиви та стартові локації.

Окрема сторінка «Про нас» містить контакти, правила безпеки в горах і поради зі спорядження.

## Як запустити проєкт

Для локального запуску бекенду виконайте наступні кроки у терміналі:

1. Створіть та активуйте віртуальне середовище:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

2. Встановіть необхідні залежності:

   ```bash
   pip install -r requirements.txt
   ```

3. Застосуйте міграції бази даних:

   ```bash
   python manage.py migrate
   ```

4. Створіть адміністратора (потрібен для створення, редагування й видалення даних):

   ```bash
   python manage.py createsuperuser
   ```

5. Запустіть сервер:

   ```bash
   python manage.py runserver
   ```

Бекенд працюватиме за адресою: http://127.0.0.1:8000/.

## Ендпоінти

### Авторизація та права доступу

Захищені ендпоінти потребують access токена в заголовку:

```
Authorization: Bearer <access_token>
```

Токен отримують через `POST /api/v1/auth/login/`. Access токен діє 5 хвилин, refresh токен 1 день. Коли access токен закінчується, новий отримують через `POST /api/v1/auth/refresh/`, не вводячи пароль знову.

| Дія | Хто має доступ |
|---|---|
| Перегляд маршрутів, масивів і стартових пунктів (`GET`) | усі, токен не потрібен |
| Створення, редагування, видалення маршрутів, масивів і стартових пунктів (`POST`, `PATCH`, `DELETE`) | лише адміністратор |
| Реєстрація, логін, оновлення токена | усі |

### Формат помилок

Усі помилки API повертаються в єдиному форматі.

`400 Bad Request` (невалідні дані, повідомлення для кожного поля):

```json
{
  "error": "Невалідні дані",
  "details": {
    "name": ["Це поле обов'язкове."]
  }
}
```

`401 Unauthorized` (немає токена, токен недійсний або прострочений):

```json
{
  "error": "Потрібна авторизація. Увійдіть в акаунт і передайте access токен у заголовку Authorization: Bearer <token>"
}
```

`403 Forbidden` (користувач авторизований, але не адміністратор):

```json
{
  "error": "Недостатньо прав для виконання цієї дії. Потрібні права адміністратора"
}
```

`404 Not Found` (об'єкта не існує):

```json
{
  "error": "Маршрут не знайдено"
}
```

`409 Conflict` (видалення масиву чи стартового пункту, до якого прив'язані маршрути):

```json
{
  "error": "Неможливо видалити гірський масив, оскільки існують пов'язані маршрути"
}
```

### Автентифікація

#### Зареєструватися

**Опис:** Створює акаунт нового користувача. Пароль зберігається в захешованому вигляді.

**Метод:** `POST /api/v1/auth/register/`

**Доступ:** усі.

**Тіло запиту:**

| Поле | Обов'язкове | Опис |
|---|---|---|
| `username` | так | унікальне ім'я користувача |
| `first_name` | ні | ім'я |
| `last_name` | ні | прізвище |
| `email` | так | коректна адреса, унікальна |
| `password` | так | не менше 8 символів, не надто проста |
| `password_confirmation` | так | має збігатися з `password` |

```json
{
  "username": "daria",
  "first_name": "Дарʼя",
  "last_name": "Синявська",
  "email": "daria@example.com",
  "password": "Hiker-Pass-2027",
  "password_confirmation": "Hiker-Pass-2027"
}
```

**Статус відповіді:** `201 Created`

**Тіло відповіді:**

```json
{
  "id": 1,
  "username": "daria",
  "first_name": "Дарʼя",
  "last_name": "Синявська",
  "email": "daria@example.com"
}
```

**Помилки:** `400` (повідомлення для кожного некоректного поля), наприклад:

```json
{
  "error": "Невалідні дані",
  "details": {
    "password_confirmation": ["Паролі не збігаються"]
  }
}
```

#### Увійти

**Опис:** Перевіряє username і пароль та повертає пару токенів.

**Метод:** `POST /api/v1/auth/login/`

**Доступ:** усі.

**Тіло запиту:**

```json
{
  "username": "daria",
  "password": "Hiker-Pass-2027"
}
```

**Статус відповіді:** `200 OK`

**Тіло відповіді:**

```json
{
  "refresh": "<refresh_token>",
  "access": "<access_token>"
}
```

**Помилки:** `401`, якщо username або пароль невірні:

```json
{
  "error": "Невірний username або пароль"
}
```

#### Оновити access токен

**Опис:** Видає новий access токен за refresh токеном, без повторного введення пароля.

**Метод:** `POST /api/v1/auth/refresh/`

**Доступ:** усі.

**Тіло запиту:**

```json
{
  "refresh": "<refresh_token>"
}
```

**Статус відповіді:** `200 OK`

**Тіло відповіді:**

```json
{
  "access": "<access_token>"
}
```

**Помилки:** `401`, якщо refresh токен недійсний або прострочений:

```json
{
  "error": "Токен недійсний або термін його дії закінчився. Оновіть токен або увійдіть знову"
}
```

#### Вийти

Окремого ендпоінта немає: при виході клієнт видаляє збережені `access` і `refresh` токени.

#### Отримати історію походів

**Опис:** Повертає заплановані та пройдені походи поточного користувача.

**Метод:** `GET /api/v1/trips/`

**Параметри (необов'язкові):**

| Параметр | Опис |
|---|---|
| `status` | `planned` / `completed` |

**Статус відповіді:** `200 OK`

**Тіло відповіді:** масив походів у тому ж форматі, що й у «Запланувати похід».

#### Позначити похід пройденим

**Опис:** Змінює статус запланованого походу на пройдений.

**Метод:** `PATCH /api/v1/trips/{id}/`

**Тіло запиту:**

```json
{
  "status": "completed"
}
```

**Статус відповіді:** `200 OK`

**Тіло відповіді:** оновлений похід у тому ж форматі, що й у «Запланувати похід».

### Про нас

**Статус:** ще не реалізовано.

#### Отримати інформацію «Про нас»

**Опис:** Повертає контакти, правила безпеки в горах і поради зі спорядження для сторінки «Про нас».
